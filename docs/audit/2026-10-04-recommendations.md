## Decision standard

Each recommendation must earn its implementation: a reproduced failure or a concrete missing capability, an independently checkable acceptance case, and a benefit that outweighs compatibility, maintenance, latency and misleading-confidence risks. Passing tests is regression evidence, not proof of universal correctness or investment performance. Improvements to test coverage are reported as detection capability, not as measured forecast or model accuracy gains. Implementations proceed individually, with focused tests before the next item and the full required checks at the end.

## 1. Credential locking — implemented

**Benefit and root cause.** The PID lock's stale-reader decision and pathname deletion are separate operations. A second process can replace the stale file with a live lock between them, so a PID/stat recheck does not establish atomic ownership. The protected callback includes token rotation and settings writes; overlap risks lost updates. A timeout must not let a paused owner resume concurrently with its replacement.

**Alternatives.** A PID lock with no stale recovery prevents this deletion race but strands credentials after crashes. Heartbeat expiry detects some compromises but does not fence a resumed callback or token refresh. A new native locking dependency adds packaging and support burden. Reuse the existing SQLite dependency for a small, separate mutex in the AI directory; using the report database would give different locks when database paths differ and would block unrelated report writes during OAuth work.

**Selected protocol.** Retain `connections.v1.json`, its schema, unknown metadata, locations and encryption. A metadata-only SQLite file occupies the permanent `connections.lock` path. Initialize a closed temporary SQLite file in the same private directory, then publish it exclusively with a hard link; never overwrite or unlink the canonical mutex. Each caller owns a dedicated connection and holds `BEGIN IMMEDIATE` across read, awaited callback and atomic JSON write. Busy acquisition yields asynchronously under the existing 40-second deadline, so one waiter cannot block another callback's event loop. Release and close in `finally`; do not replay callbacks with possible remote effects. OS ownership is released after process termination.

**Risks and acceptance gates.** Existing numeric/partial/unknown locks fail closed with stopped-server migration guidance; credential bytes remain intact. Old binaries do not understand this protocol, and an old in-flight deletion cannot be retroactively fenced, so quiescent upgrade/downgrade is required. Hard-link publication assumes a supporting local filesystem and fails closed otherwise. No network-filesystem guarantee is offered. Raw filesystem reads/closes of a published mutex are forbidden because of [SQLite's documented POSIX lock-close hazard](https://www.sqlite.org/howtocorrupt.html#posix_advisory_locks_canceled_by_a_separate_thread_doing_close). Real-process tests must prove cold-start serialization, no lost updates, held-lock exclusion, killed-holder recovery before/after writes, alias unlink safety, failed-write preservation, legacy refusal and same-process asynchronous progress. Native Windows and Linux verification are required before claiming F08 fixed; macOS requires a separate run. Remote token rotation followed by a crash before local persistence remains a separate distributed-transaction limitation.

**Measured verification.** A legacy-lock refusal case first failed against the old protocol because the mutation ran. The new protocol refuses it and preserves the bytes. Six focused mutex/store/OAuth/Gemini/selection files pass 114 tests on native Windows, including three simultaneous child processes making four serialized scratch writes each, held-owner timeout without callback entry, killed owners before/after JSON rename, killed publishers before/after hard-link publication, and same-process awaited callbacks. A real alias unlink while the canonical reservation was held did not admit a contender; simulated denied cleanup leaves only a harmless marker alias. Initialization, rollback, close, callback, JSON write/rename and DPAPI failures preserve primary failures and saved credentials. The actual Windows DPAPI round trip passes. These tests use temporary directories and scratch JSON, not user tokens or remote refresh calls. Focused coverage is mutex 100% statements/branches/functions/lines and store 100%/95%/100%/100%; scoped typecheck, lint and the literal risk inventory pass. Root documentation/release/inventory checks pass 32 tests. Linux CI and whole-repository checks remain pending at this checkpoint.

**Cleanup and compatibility.** Remove the obsolete PID-probing/unlink loop and replace its protocol-specific tests with native-ownership and failure tests; do not delete credential files or change their format. Canonical mutex deletion is prohibited during operation. Safe temporary-marker cleanup can leave an orphan if Windows sharing rules or a crash prevent deletion; no token data is stored there. User-facing upgrade/downgrade steps are in [Privacy](../PRIVACY.md).

Add six issuer categories and twelve annual periods with frozen, manually transcribed inputs and independent arithmetic literals. A broad live-download harness would be more fragile, would not be offline, and could confuse revised current data with historical knowledge. A direct SEC companyfacts request returned 403; no access workaround or repeated probing was used. These excerpts deliberately validate normalized arithmetic and routing, not raw XBRL extraction. A raw-payload parser cohort remains separate work.

**Independent procedure.** Retain statement units and multiply amounts, but not EPS, by the explicit source-unit multiplier. Freeze separate absolute base-currency references so scale mistakes cannot cancel out of ratios. Compute margins as the relevant income divided by revenue; FCF as OCF plus signed capex, withholding when an operand is missing; annual growth as `(new / old - 1) * 100` only for valid endpoints. Compute latest DuPont using fiscal endpoint averages: net margin `NI/revenue`, turnover `revenue/averageAssets`, leverage `averageAssets/averageParentEquity`, ROE `NI/averageParentEquity * 100`. Two fiscal endpoints are the app's convention, not proof of the issuer's published average-balance ratio. Expected values are stored literals derived without production imports, and tests must not regenerate them from the implementation.

**Acceptance and limitations.** Exercise absolute units, margins, FCF signs and missingness, annual ordering/growth, two-year history withholding of a three-year benchmark, endpoint-average DuPont, and bank/insurer/REIT/loss/ADR policies. Challenge copied inputs with a 1,000-fold PLD scale error, JPM common equity substituted for parent equity, reversed or missing Apple capex, and MetLife missing capex imputed to zero. These are sensitivity checks, not discovered production defects. The value is independently anchored regression detection; no new predictive accuracy, universal provider accuracy, quarterly parser coverage, historical vintage coverage or human-reviewed model benchmark is claimed. No price, market cap or statement is borrowed from DEMO under a real issuer name.

**Measured verification.** Maintained inputs are [annual-reference-cohort.json](../../fixtures/financial/annual-reference-cohort.json); the [30-case suite](../../tests/stageB.realIssuerReferences.test.ts) passes, as do typecheck and scoped lint. A second reviewer recomputed all 102 numerical literals with alternate arithmetic and confirmed the source bases. Review also caught vacuous empty suppression subsets: the final suite explicitly keeps appropriate manufacturer/ADR/loss margins and growth eligible and checks financial-route exclusions and eligible sector metrics. Five ignored copies of this same maintained harness with altered fixture inputs produced ten expected failing tests and 140 passing tests; every intended error was caught without changing production or the maintained fixture. Examples: PLD revenue 8,790,127,000 became 8,790,127,000,000 under the scale error; JPM house ROE 16.133575% became 17.103257% under the common-equity substitution; Apple FCF 98,767,000,000 became 124,197,000,000 with reversed capex; MetLife's missing FCF became a false 17,092,000,000 when capex was imputed zero. These negative controls demonstrate detection by the new references, not five newly found production bugs. No production formula or version changed for this item.

## 3. Historical knowledge cutoff — defer the historical report feature

**Evidence.** A controlled companyfacts example with FY2023 revenue 100 filed on 2024-02-01 and an amendment to 120 filed on 2025-02-01 returns 120 even when statement construction receives `asOf: 2024-06-01`. That option currently concerns observation/share-basis handling, not a publication cutoff. This is a limitation for retrospective analysis; latest-filed selection remains appropriate for the current-report workflow. FRED requests have observation start/end options but no real-time vintage option. An observation's period end does not establish when its value became known.

**Alternatives and tradeoffs.** A SEC-only `knownByDate` filter is small and could prevent future amendments in that extractor, but would not constrain estimates, quotes, macro revisions, filing/news text, corporate actions or other providers. Exposing it as a historical report would add false confidence. Adding an unused public option would also create a compatibility promise before its downstream contract exists. A complete mode needs an explicit end-of-day versus intraday cutoff (companyfacts filing dates are date-only), provenance for each input's publication time, cache identities containing the vintage, and failure rather than latest-data fallback where historical retrieval is unavailable. It is substantially more than a date filter.

**Decision.** Do not expose a partial historical mode or change current latest-filed behavior in this batch. The benefit is credible, but a usable end-to-end implementation cannot yet be shown to outweigh the risk of hidden look-ahead. First freeze publication-aware reference cases and define provider coverage. Acceptance for a future implementation: pre/post amendment cases, same-day cutoff semantics, derived-quarter operands, historical split basis, macro vintages and rejection of current-only fallbacks, then a full report with every time-sensitive input bounded. This deferral is not a claim that historical backtesting is already supported.

## 4. Forecast calibration — retain explicitly unbacktested priors

**Evidence.** `src/pipeline/stageB/projections.ts` stamps `UNBACKTESTED_SCENARIO_PRIOR_2026_07`. The 25/50/25 weights are a display prior. The engine already estimates dispersion from consecutive history and suppresses inappropriate sector routes. There is no verified corpus of historical forecasts, contemporaneously available inputs and subsequently realized outcomes in the repository. Synthetic DCF correctness cases cannot establish predictive skill.

**Alternatives and tradeoffs.** Tuning weights against today's restated history risks leakage; tuning and measuring on the same small issuer set risks overfitting. A generic scorer without admissible observations would add maintenance while returning no credible accuracy result. A useful study must preserve original forecasts, accounting basis, issuer selection (including failed/delisted issuers), horizon and publication dates; compare revenue and margin errors with flat/rolling-history benchmarks; report sample counts and bias alongside absolute error; and keep chronological holdouts separate from tuning. Scenario-range coverage alone cannot validate the individual bull/base/bear weights as probabilities.

**Decision.** No probability, projection or scoring-formula change is justified by current outcome evidence. Defer calibration until the temporal prerequisites in item 3 and an outcome corpus exist. [Hyndman and Athanasopoulos' rolling-origin evaluation](https://otexts.com/fpp3/tscv.html) supports training only on earlier observations; this principle applies here, but their examples do not validate this app's forecasts. A future implementation must show repeatable out-of-sample gains by horizon and route, including underperformance, before adopting tuned parameters.

## 5. AI factual-quality benchmark — defer an accuracy score

**Evidence.** The existing verification code matches citations and performs bounded direction, year, unit and named-person checks. It reports checked counts separately and explicitly calls citation coverage traceability rather than correctness. These checks can detect particular contradictions but do not determine whether arbitrary prose is entailed by a filing, whether a material risk was omitted, or whether different runs are equally useful.

**Alternatives and tradeoffs.** More controlled negative fixtures can strengthen a specific detector when a missed case is reproduced. A model grading its own output, or an agent-created label set described as human reviewed, would not establish independent factual quality. Citation presence is an especially misleading substitute: a real URL can accompany an unsupported claim. A full benchmark needs independently reviewed claim/support labels, numeric and period tolerances, explicit abstentions, an omission rubric with known material risks, and frozen model/prompt/input versions for repeatability. It also needs separate precision, coverage and omission measures; one overall percentage can reward silence or hide unchecked claims.

**Decision.** Do not add an unvalidated app accuracy score or duplicate the existing deterministic suite with a synthetic score presented as model performance. No paid model calls are needed for this decision. A later offline benchmark may replay saved, consented model outputs against a reviewed answer set; live repetitions would require the permitted OAuth path and a budget/latency assessment. [FActScore](https://arxiv.org/abs/2305.14251) motivates checking individual facts against reliable evidence, but its biography evaluation is not a validated financial-analysis benchmark and does not measure omitted investment risks. The current task establishes no measured improvement in generated prose accuracy.

## 6. Calendar alignment — implemented

**Design and alternatives.** Replace `day >= 26` with the final regular NYSE session for each month. Both issuer and benchmark must supply that session; no price is filled. A rule excluding the entire current month would also remove partial periods but would discard a valid final session after it completed. A full external calendar dependency would add maintenance and supply-chain cost for a small set of relevant month-end rules. The bounded implementation covers weekends, Memorial Day and Good Friday, and retains early closes. It explicitly discloses exceptional-closure/non-US limitations. [NYSE's calendar](https://www.nyse.com/trade/hours-calendars) establishes the session conventions; the Easter calculation is a deterministic way to locate the relevant Good Fridays, not a forecast of exceptional exchange closures.

For inferred monthly/quarterly/annual FRED series, select lag operands by calendar period. A wholly absent period withholds the affected change; it cannot move another row into its place. Duplicate rows in one inferred slot are ambiguous and withheld. Daily/weekly/biweekly observation-count formulas and the documented sparse-frequency limitation remain. The [official FRED transformations](https://fred.stlouisfed.org/docs/api/fred/series_observations.html) govern the formulas; this change corrects operand selection rather than replacing them.

**Files and acceptance.** `src/pipeline/stageB/betaEstimate.ts`, `src/providers/fred.ts`, their tests and the keyless integration fixture. Test the May 28 partial-month distortion; genuine Memorial Day and Good Friday month ends; early close/leap year/weekend dates; either series missing its final session; absent monthly, quarterly and annual operands; duplicate/invalid dates; and unchanged daily conventions. Tests first reproduced 19 failures among 93 cases; the expanded two-file suite then passed 98 cases. The broader keyless test exposed an existing fake Yahoo history containing non-session month-end bars. Its terminal-month samples were corrected to represent trading sessions rather than relaxing production checks; the broader six-file provider/finance run then passed 206 tests. Scoped lint and type checking passed.

**Version and regression evidence.** Report 1.9.0 and payload 1.10.0 prevent reuse of older financial conventions; saved reports are read unchanged. New legacy-version tests first failed for reuse/comparability, then passed. The audited DEMO comparison changes only `report.meta.specVersion`; the Stage C finance and provenance hashes are unchanged, and its serialized prompt gains one byte from the longer version string. Four integration/documentation files passed 170 tests after updating this explicit version contract. These results demonstrate removal of the controlled alignment errors, not improved returns or a universal accuracy estimate.

**Independent review follow-up.** Date equality alone still accepted a final-session intraday Yahoo bar. A second controlled case changed beta 1.300 to 1.152 on May 31. Nine new helper/caller cases failed before the repair. The keyless caller now passes an explicit UTC observation-day cutoff; both issuer and benchmark bars must be earlier than it, before month-end selection. Current/future bars cannot choose the beta window. A malformed explicit cutoff returns a disclosed gap. Pure historical callers without a cutoff must supply settled bars. This conservative policy waits until the next UTC day even after market close because daily bars have no reliable settled-session signal; quote and chart histories remain intact. The alternative of inferring an intraday exchange clock would add timezone/early-close complexity without a source completion contract. Three focused files then passed 125 tests, including next-day admission, one-sided current bars and keyless quote/chart preservation. Their independently constructed shock fixture changes 1.1358035108567004 without the cutoff to 1.299999999999998 with it; it is a different sample pattern from the reviewer's 1.152 case. Typecheck and scoped lint pass; the root's 13 documentation and immutable-delta checks also pass with no new baseline delta. This closes the reproduced current-day distortion while retaining the disclosed exchange-calendar limits.

## 7. Evidence usability — implemented

**Observed gap.** Grade reasoning records supporting numbers, but their full source is in a hover title and some provenance fields are absent. The DCF headline has the same limitation. Price and relative-strength plots expose canvas images without a textual table of their values. This limits keyboard and nonvisual inspection. Composite scores already show weights and a driver audit table; duplicating those or inventing a ranking of grade influence would add clutter without new evidence.

**Selected scope and alternatives.** Reuse native disclosures to expose recorded grade-input and DCF provenance, including source ID, observation date, period and missing metadata. Keep the current layout as the default and the Research workspace setting. Add optional price and relative-strength tables that consume the same prepared numeric arrays as the canvas. A separate table normalizer risks drift; rounding to displayed ticks hides actual submitted values. A permanently rendered full-history table would increase initial DOM size and mobile clutter, so mount it only when opened and paginate at 30 rows, newest page first, with every row reachable. This bounds expanded DOM cost but does not reduce the report's data payload.

**Acceptance and limits.** Verify exact chart/table values, sorting/deduplication, valid zero versus missing volume, sparse relative-strength observations, actual per-series baseline dates, escaping, empty and legacy provenance, lazy closed markup and pagination boundaries. Numeric preparation enters risk coverage under unchanged thresholds. Browser verification must cover Current and Research workspace, desktop and narrow mobile, native keyboard disclosure operation, pagination and table overflow. Prices do not invent a currency absent from chart inputs. Missing plotted observations say unavailable; existing lines may still visually bridge missing dates, and a series beginning later may retain its own later rebasing date. This item exposes those facts without changing plot semantics or calling them aligned same-date baselines. Source strings remain escaped text rather than fabricated links or inferred calculation lineage. Report exports remain based on saved report data, independent of whether a client disclosure is open.

**Measured verification and review.** The initial rendered-control cases reproduced ten failures among twelve tests. After implementation, an expanded fifteen-file group passes 330 tests, including component-effect capture at the chart `setData` boundary, exact model/table values, both designs, lazy markup, pagination, escaping, print and exports. The new numeric preparation module has 100% statement/branch/function/line coverage in the focused run and is explicitly in both risk manifests; no threshold was reduced. Typecheck and scoped lint pass. Review found and removed a newly introduced quadratic volume-color lookup, using a single date lookup map; the original plotting arithmetic and colors are retained. Review also corrected unresolved-citation wording to “not citation-traced,” removed a redundant invalid closed disclosure reference and corrected the old comment implying every RS series has the same baseline date. Independent source review found no further actionable defect. Actual browser interaction and the final full gates are separate release evidence recorded in [PR #6](https://github.com/eligorelick/Thesis-AI-equity-research/pull/6), not inferred from server-rendered markup tests.

**Narrow-screen boundary.** At 390px, the existing Current sidebar leaves only about 22px for the chart-table region; the new table remains contained without adding page overflow, but that layout is materially cramped. Research workspace provides about 273px for the same region and supports keyboard horizontal scrolling. The chosen Current layout is retained; a responsive Current navigation redesign remains deferred. Native controls and semantic tables are not a claim of comprehensive assistive-technology testing or WCAG conformance.

Windows local product/core-coverage runs use one worker as in Windows CI; the Linux CI job retains the repository defaults. Its exact prefix was updated from 1.9.0 to 1.10.0 while retaining the eight-hex fingerprint constraint. The first local full run also exposed verification-wrapper mistakes: disabled startup work and app-data inside the repository conflicted with default-behavior tests, and a README editing operation had introduced CRLF despite its required LF. Restore the declared test defaults, isolate runtime data outside the repository, reserve startup suppression for the build/preview, and restore LF without changing generated content. All five affected files then pass 167 tests. No production behavior, timeout, coverage floor or assertion was relaxed to obtain a pass; the final full runs must follow these corrections.

No live inference, private OAuth refresh or live provider entitlement validation is claimed. Native macOS mutex behavior, network filesystems and sudden power-loss durability are unverified; the mutex's release gate covers native Windows and Linux process behavior on local filesystems. Current reports still use latest available data, forecast scenario weights remain unbacktested priors, and citation tracing is not a factual-accuracy score. Historical provider vintages, raw cross-sector XBRL reference captures, forecast outcomes, a reviewed AI benchmark and RS gap/rebase policy changes remain separate deferred work. Passing the checks supports the bounded changes; it does not guarantee financial accuracy, predictive gains or absence of regressions.
