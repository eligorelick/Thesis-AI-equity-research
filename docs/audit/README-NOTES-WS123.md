# README notes — WS1–WS3 (model registry, presumed spend, per-request admission)

Corrections `README.md` needs after the WS1–WS3 remediation. This workstream
does not edit `README.md`; the README rewrite folds these in. Sentences below
are written to be used close to verbatim. Every figure here is generated by
`npm run docs:pricing` from `config/models.json` and the reservation code —
regenerate rather than retyping.

## 1. The generated-pricing markers do not exist

`scripts/docs-pricing.mjs` replaces a block delimited by

```
<!-- BEGIN GENERATED: pricing -->
<!-- END GENERATED: pricing -->
```

`README.md` contains neither marker, so `npm run docs:pricing -- --write`
throws `README is missing the <!-- BEGIN GENERATED: pricing --> / <!-- END
GENERATED: pricing --> markers` and writes nothing. The doc-lint contract in
D-22 ("`npm run docs:config`, `docs:commands`, `docs:pricing` regenerate marked
README sections") is therefore unenforceable for pricing.

**Action:** insert the two markers around the reservation table (§ 3 below), so
the block is generated rather than hand-maintained.

**Knock-on:** `.env.example` (the comment above `THESIS_MAX_JOB_COST_USD`) tells
the operator to "Size these off the generated table in the README (`npm run
docs:pricing`)". Today that sentence points at nothing. It becomes true once the
markers exist; until then it should say "run `npm run docs:pricing` and size
these off its output".

## 2. `ANALYSIS_MODEL` no longer accepts a dated snapshot for most models

The README says (§ "Configuration", prose under the environment table):

> It accepts `auto` or one of the five priced aliases — `claude-opus-5`,
> `claude-opus-4-8`, `claude-sonnet-5`, `claude-fable-5`, `claude-haiku-4-5` —
> optionally as an eight-digit dated snapshot such as `claude-opus-5-20260115`.

Two things are wrong. The alias list is missing `claude-fable-5-1` (six active
models, not five), and the dated-snapshot clause is false for every family from
the 4.6 generation on — `claude-opus-5-20260115` does not exist and is now
rejected at settings write and at model resolution (D-02). Only
`claude-haiku-4-5-20251001` is a real dated id. Replace with:

> `ANALYSIS_MODEL` is not a free-form Anthropic model ID. It accepts `auto` or
> one of the six active ids in the model registry — `claude-fable-5-1`,
> `claude-fable-5`, `claude-opus-5`, `claude-opus-4-8`, `claude-sonnet-5`,
> `claude-haiku-4-5`. Dated snapshot ids exist only where the registry lists
> them: `claude-haiku-4-5-20251001` is accepted, and from the 4.6 generation on
> the dateless id *is* the pinned snapshot, so a dated form such as
> `claude-opus-5-20260115` is refused. A refused value is not silently ignored:
> the run degrades to a data-only report whose execution metadata carries a
> `model-rejected` adjustment naming the value and the accepted ids, and the
> Settings page shows the same sentence beside the stored value.

The `auto` order in the same paragraph must gain Fable 5.1 (D-03):

> `auto` resolves against the models your key can reach, preferring
> `claude-opus-5`, then `claude-opus-4-8`, then `claude-sonnet-5`, then
> `claude-fable-5-1`, then `claude-fable-5`.

## 4. The paragraph saying a usable job cap is impossible is the WS3 finding

The README currently says:

> Because these are worst-case bounds rather than expected charges, a job cap
> small enough to act as an everyday budget is not achievable: one synthesize
> pass alone reserves $373.68, so `THESIS_MAX_JOB_COST_USD` set near a typical
> run's actual cost rejects every job before it starts.

That is exactly the defect D-10 fixed. Replace with:

> In the default `request` reservation mode each provider request is admitted
> on its own, so a reservation is one request's maximum — $3.86 for a Sonnet 5
> analyst request — rather than a whole pass's worst case. A per-job cap of a
> few dollars is therefore usable as an everyday budget: a complete measured
> run settled at $1.43. Set `THESIS_RESERVATION_MODE=pass` and the old bound
> returns (a Sonnet 5 analyst pass reserves $138.96), which is kept for one
> release as a fallback, not as a recommendation.

## 5. A launched call no longer holds its reservation until settlement

The README says:

> A provider-launched call retains its reservation until exact settlement or
> lease expiry so another process cannot spend the same budget prematurely;
> only an exit before provider launch releases a reservation as unbilled.

The "or lease expiry" half now means something different (D-07): an expired
unsettled reservation is not released, it is converted into a `cost_log` row of
kind `presumed` at the full reserved maximum, which every admission path keeps
counting. Replace with:

> A provider-launched call retains its reservation until it settles; only an
> exit before provider launch releases a reservation as unbilled. If the
> process holding a reservation dies, the reservation is **not** returned to
> the caps — Anthropic may well have billed it — so it is recorded as presumed
> spend at its reserved maximum and keeps counting against every cap. Only
> evidence lowers it: a late settlement for the same attempt, or
> `npm run costs:reconcile` against the Usage & Cost API. A report whose run
> contains presumed spend says so: `meta.presumedCostUsd` names the amount and
> the missing-data manifest carries a `cost.presumed` entry, so the reader can
> see which part of the total is an upper bound rather than a charge.

## 6. `THESIS_PAID_PASS_LEASE_SECONDS`: wrong floor, missing invariant

The environment table row reads:

> | `THESIS_PAID_PASS_LEASE_SECONDS` | Paid-call lease TTL; `601`–`2147483` seconds | Defaults to `900` |

The floor is now **660**, not 601: the lease must outlive the 600-second
provider request timeout *plus* the 60-second margin an aborted stream needs to
settle its reported usage (`MIN_PAID_PASS_LEASE_SECONDS` in
`src/pipeline/leaseTiming.ts`). The relation to the job lease is validated at
startup (D-08) and undocumented. Replace the two rows with:

> | `THESIS_PAID_PASS_LEASE_SECONDS` | Paid-call lease TTL; `660`–`2147483` seconds | Defaults to `900` |
> | `THESIS_JOB_LEASE_SECONDS` | Job-claim lease TTL; `600`–`2147483` seconds, and never below `THESIS_PAID_PASS_LEASE_SECONDS` | Defaults to `900` |

and add, next to them:

> These lease relations are checked when configuration is parsed, and a process
> that violates one fails to start rather than running with a paid lease that
> can outlive the job claim that owns it.

row in the environment table or a sentence in the section named.

| Missing | Where it belongs | What to say |

## 8. Two smaller corrections

- The model-floor paragraph says the judge pass "is raised to `claude-sonnet-5`".
  That id now lives in the registry (`judgeFloorModelId`); the README should say
  "raised to the registry's judge floor (currently `claude-sonnet-5`)" so the
  sentence stays true after a registry refresh.
- The prose introducing the reservation table says reservations "use a
  worst-case 108-request exposure bound (SDK retries, transport retries, and
  pause resumptions)". In `request` mode nothing reserves a pass-level bound at
  all; the 36-request worst case is reported in the pricing table and never
  reserved.
